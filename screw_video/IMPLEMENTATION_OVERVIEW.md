# 视频螺丝计数项目实现说明

## 1. 项目目标

本项目面向动态视频中的螺丝分类与计数任务。输入为一个视频文件夹，输出包括：

- 每段视频中 5 类螺丝的计数结果
- 每段视频一张带有检测/跟踪结果的可视化掩膜图
- 全部视频的总处理时间

整体目标不是只做单帧检测，而是利用时序信息减少重复计数，并在遮挡、短暂丢失、目标靠近边界等情况下保持较稳定的统计结果。

## 2. 总体思路

当前方案采用“检测 + 跟踪 + Re-ID + 计数过滤”的多阶段结构：

1. 使用 YOLO 对每一帧进行螺丝检测与类别预测。
2. 在进入跟踪器前，先过滤掉位于画面边缘的检测框，减少目标被截断时的误检。
3. 使用 ByteTrack 进行多目标跟踪，给同一螺丝分配局部轨迹 ID。
4. 在跟踪基础上引入 OSNet Re-ID，对目标外观特征进行提取和匹配，将局部轨迹 ID 进一步映射为全局 ID。
5. 对每条轨迹做类别投票，并在最终计数阶段过滤掉长度过短的轨迹，抑制瞬时误检和短暂漂移带来的重复计数。

这一设计的核心出发点是：

- YOLO 负责“看见目标”
- ByteTrack 负责“保持短时连续性”
- Re-ID 负责“断轨后重新认回同一个目标”
- 轨迹投票与短轨迹过滤负责“提高最终计数稳定性”

## 3. 系统流程

### 3.1 检测阶段

检测模块采用训练好的 YOLO 权重，对视频帧输出：

- 螺丝位置框
- 螺丝类别
- 检测置信度

检测阶段主要解决“目标是否存在、属于哪一类”的问题，为后续跟踪与计数提供基础输入。

### 3.2 边缘框过滤

在工业视频中，靠近画面边缘的目标往往存在截断、部分可见、形状不完整等问题。这类目标容易导致：

- 检测类别不稳定
- 跟踪框漂移
- 新旧轨迹切换频繁
- 重复计数

因此在进入 ByteTrack 之前，系统会忽略距离画面边界过近的检测框。这样做虽然会牺牲少量边缘区域召回率，但能明显降低由截断目标带来的误检测和误关联。

### 3.3 跟踪阶段

跟踪模块使用 ByteTrack。其作用是把相邻帧中的同一目标连接成轨迹，从而把“单帧检测结果”变成“跨帧目标实例”。

相较于仅依赖检测结果直接累加，跟踪机制有两个明显优势：

- 避免同一螺丝在连续多帧中被重复统计
- 为后续轨迹级类别投票和轨迹长度过滤提供依据

### 3.4 Re-ID 阶段

仅靠常规跟踪器，在以下情况中仍然容易出现 ID 断裂：

- 目标之间相互遮挡
- 螺丝运动速度变化较大
- 检测器某几帧漏检
- 局部轨迹重新初始化

因此项目中加入了基于 OSNet 的 Re-ID 模块。

Re-ID 的工作方式如下：

- 依据当前检测框，从框内裁剪目标区域
- 将裁剪图像送入 OSNet 提取外观特征向量
- 使用余弦相似度将当前轨迹与历史全局轨迹进行匹配
- 若匹配成功，则沿用已有全局 ID
- 若匹配失败，则创建新的全局 ID

当前实现中，Re-ID 会持续更新轨迹的外观原型，使其能随视角、尺度和局部外观变化逐步适配，而不是长期依赖初始帧特征。

### 3.5 计数阶段

最终计数不是直接按照检测结果累加，而是按照轨迹级别统计。

主要包含两个策略：

#### 轨迹类别投票

同一目标在不同帧中可能出现类别抖动。为减少单帧误分类对最终结果的影响，系统对同一轨迹中的类别结果进行投票，使用该轨迹最常出现的类别作为最终类别。

#### 短轨迹过滤

很多误检只会存在 1 到 2 帧，或者刚出现就消失。若直接计入结果，会明显放大重复计数和噪声计数。因此系统提供最小轨迹长度约束，只统计持续时间达到阈值的轨迹。

这一步对减少瞬时误检尤其有效。

## 4. 输出设计

### 4.1 计数结果

系统按视频名输出一个字典，每个视频对应一个长度为 5 的列表：

`[Type_1, Type_2, Type_3, Type_4, Type_5]`

该结果可直接满足作业要求的自动评测格式。

### 4.2 掩膜可视化

对于每段视频，系统会保存一张接近视频中间位置的可视化图像，展示：

- 当前检测到的螺丝位置
- 轨迹 ID
- 螺丝类别

这一输出主要用于定性展示模型是否正确定位并稳定跟踪目标。

### 4.3 时间统计

系统记录处理全部视频的总耗时，用于评价整体吞吐效率。

## 5. 当前方案的关键改进点

相较于基础的“检测后直接计数”方案，当前实现的主要增强点包括：

- 引入 ByteTrack，利用时序信息避免重复计数
- 引入 OSNet Re-ID，提高断轨后的重新关联能力
- 使用边缘框过滤，降低截断目标带来的误检
- 使用轨迹类别投票，减弱单帧分类抖动的影响
- 使用短轨迹过滤，抑制瞬时误检造成的计数噪声

这些设计共同服务于一个目标：让最终统计更加接近“按真实目标个数计数”，而不是“按检测框个数累加”。

## 6. 方案特点与权衡

当前方法的优势在于结构清晰、模块独立、便于调试和逐步优化：

- 检测负责识别
- 跟踪负责连续性
- Re-ID 负责重关联
- 计数策略负责结果稳定性

同时该方案也存在典型权衡：

- 增加 Re-ID 后，精度提升和运行时间之间需要平衡
- 边缘过滤会降低部分边缘目标的召回率
- 短轨迹过滤会压制误检，但阈值过大时也可能漏掉真实短时目标
- Re-ID 对外观差异较小的小目标场景有效，但对框质量和检测稳定性依然敏感

因此，当前系统并不是依赖单一模块解决所有问题，而是通过多模块协同，把误差分散到不同环节中逐步削弱。

## 7. 适合汇报时强调的结论

在汇报展示中，可以将本项目概括为以下几点：

- 这是一个基于视频时序信息的螺丝计数系统，而不是单帧检测系统。
- 系统通过“检测、跟踪、重识别、投票、过滤”五个环节逐步提高计数稳定性。
- ByteTrack 解决短时连续问题，OSNet Re-ID 解决断轨后的身份恢复问题。
- 最终计数基于轨迹而不是基于检测框，因而更接近真实零件数量。
- 当前实现特别针对工业视频中常见的重复计数、边缘误检、短时噪声等问题进行了专门处理。

## 8. 后续可优化方向

后续若继续优化，可重点考虑以下方向：

- 针对螺丝数据进一步训练专用 Re-ID 特征，而不是直接使用通用 OSNet 权重
- 融合检测置信度、轨迹稳定度与外观相似度，构建更稳健的关联策略
- 针对遮挡和出入画面场景设计更细的计数区域规则
- 进一步压缩 Re-ID 开销，提升整体处理速度
- 基于开发集系统化调节 `edge_margin`、`min_track_length`、`reid_match_thresh` 等关键参数
